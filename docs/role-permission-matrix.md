# Role and Permission Matrix

## 1. منهج التحكم

الدور يوفّر مجموعة مبدئية فقط؛ القرار النهائي يقوم على `permission + tenant + scope + policy + approval limit`. تفصل المنصة بين الإنشاء والمراجعة والاعتماد للعمليات المحددة في السياسة. لا يمنح المنصب الإداري حق حذف سجلات التدقيق أو تجاوز عزل المستأجر.

| الدور | نطاق الرؤية | نقاط القوة | القيود الأساسية |
| --- | --- | --- | --- |
| Super Admin | المنصة، بلا دخول افتراضي للدفاتر | إدارة المستأجرين والخطط والدعم المقيد | دخول الدعم مؤقت ومسجل ومسوغ |
| Company Admin | شركته | المستخدمون والإعدادات وسياسات الاعتماد | لا يرحّل أو يعتمد بالضرورة قيوداً محاسبية |
| مدير الحسابات | الشركة أو الفروع المخولة | اعتماد القيود، الإقفال، التقارير | يخضع لفصل المهام والحدود |
| محاسب | النطاق المخول | إنشاء مستندات وقيود ومسودات | لا يعتمد ما أعده عند تفعيل SoD |
| محاسب قانوني | مراجعة محددة | مراجعة وإبداء ملاحظات واعتماد وفق السياسة | لا يعدل الأصل بعد المرحلة المعتمدة |
| مدير عام | لوحة تنفيذية وتقارير | اعتماد عالٍ ورؤية مؤشرات | لا يملك تعديل المحاسبة افتراضياً |
| مبيعات | العملاء والعروض والفواتير المخولة | إنشاء وإرسال ضمن السياسة | بلا دفتر عام أو إعدادات ضريبية |
| قراءة فقط | نطاق القراءة | تقارير ومستندات مرئية | بلا إنشاء أو اعتماد أو تصدير حساس عند الحظر |

## 3. سياسات فصل المهام

تقبل الشركة قواعد قابلة للضبط، مثل منع منشئ قيد يتجاوز حداً مالياً من اعتماده، أو اشتراط موافقة مدير الحسابات لإشعار دائن يتجاوز حداً آخر. يحتفظ طلب الاعتماد بالمُنشئ والمراجع والموافق، ومستوى السياسة، والمبلغ، والنتيجة، والسبب، والطابع الزمني. لا يكفي تبديل الدور لتجاوز تعارض المصالح؛ يفحص النظام معرف المستخدم وسياق المستند.
